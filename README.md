# 💸 Калькулятор долгов (Telegram-бот + DeepSeek + Supabase)

Бот принимает сообщения вида «Леша должен Диме 3 рубля», разбирает их через **DeepSeek**,
складывает структуру в **Supabase** и умеет показывать и считать долги (с взаимозачётом
и валютой по умолчанию).

```
Telegram → bot.py ── DeepSeek (chat/completions, JSON) ──► {"from":"Леша","to":"Дима","currency":"BYN","amount":3.0}
              │
              └── Supabase (PostgREST) → таблицы debts / bot_settings
```

| Файл | Что делает |
|---|---|
| `bot.py` | запуск бота, маршрутизация команд, `--check`, `--demo`, команды вебхука |
| `webhook.py` | режим вебхука: WSGI-приложение (Vercel, PythonAnywhere, gunicorn) + `--serve` |
| `api/telegram.py` | точка входа для Vercel: отдаёт `webhook.app` по адресу `/api/telegram` |
| `telegram_api.py` | Telegram Bot API: `getUpdates`, `sendMessage`, `setWebhook`/`deleteWebhook` |
| `deepseek.py` | разбор сообщений через DeepSeek + офлайн-эвристики (фолбэк) |
| `storage.py` | Supabase через REST (PostgREST) + хранилище в памяти для тестов |
| `debts.py` | нормализация имён, взаимозачёт, итоги, тексты ответов |
| `members.py` | участники чата: сопоставление имён с `@никами` и id, подсказки для ИИ |
| `config.py` | настройки из `.env` и переменных окружения |
| `db/schema.sql` | таблицы `debts`, `bot_settings`, `bot_state`, RLS, индексы |
| `tests/test_pipeline.py` | тесты без внешних сервисов (`unittest`) |

Зависимость всего одна — `requests` (работает и на ПК, и на телефоне в Termux, и на VPS).

## Быстрый старт

1. **Бот.** В Telegram у `@BotFather`: `/newbot` → получить токен.
2. **DeepSeek.** platform.deepseek.com → *API keys* → создать ключ (нужен баланс).
3. **Supabase.** Создать проект → *SQL Editor* → выполнить `db/schema.sql`
   → *Project Settings → API*: взять `Project URL` и ключ **service_role** (secret).
4. **Настройки.** Скопировать `.env.example` в `.env` рядом с `bot.py` и заполнить:
   ```ini
   TELEGRAM_BOT_TOKEN=123456789:AA...
   DEEPSEEK_API_KEY=sk-...
   SUPABASE_URL=https://xxxx.supabase.co
   SUPABASE_SERVICE_KEY=eyJhbGciOi...   # service_role, не anon!
   DEFAULT_CURRENCY=BYN
   ALLOWED_USER_IDS=                    # пусто = всем; иначе список id через запятую
   ```
   Узнать свой user id можно у `@userinfobot`.
5. **Проверка и запуск:**
   ```powershell
   pip install -r requirements.txt
   python bot.py --check     # проверяет .env, Telegram, DeepSeek, Supabase
   python bot.py --demo      # демонстрация без Telegram (в памяти, офлайн-разбор)
   python bot.py             # рабочий режим (Ctrl+C — остановка)
   ```

## Что понимает бот

| Что написать | Что произойдёт |
|---|---|
| `@бот Леша должен Диме 3 рубля` (в группе) | долг: Леша → Дима, 3.00 BYN — в группах бот реагирует только на обращение |
| `Леша должен Диме 3 рубля` (в личке) | долг: Леша → Дима, 3.00 BYN (обращаться не нужно) |
| `Леша должен Диме 3 рубля` | долг: Леша → Дима, 3.00 BYN |
| `Маша заняла у Пети 10$` | долг: Маша → Петя, 10.00 USD |
| `Петя должен Оле 10,50 долларов` | долг: Петя → Оля, 10.50 USD |
| `Леша должен Диме 7` | 7.00 в валюте по умолчанию |
| `Леша вернул Диме 3 рубля` | возврат долга: уменьшает долг Леши перед Димой (годится «отдал», «погасил», «рассчитался с Димой на 5») |
| `Лешак должен Диме 3 рубля` | если в чате есть «Леша Козлов» (@kozlovAlex) и «Дмитрий Болт» (@bdzmity), запись привяжется к их id — см. «Кто есть кто в чате» |
| `я должен Диме 3 рубля` | долг записывается на автора сообщения (его id и имя) |
| `/currency USD` или `валюта по умолчанию доллар` | меняет валюту по умолчанию для чата |
| `/debts` или `покажи долги` | отчёт: сальдо с взаимозачётом, итоги по людям, отдельный блок возвратов |
| `/undo` | удаляет последнюю запись этого чата (например, если продиктовали с ошибкой) |
| `/reset` | удаляет все записи этого чата |
| `/help`, `/start` | справка |

Валюта, если она не указана в сообщении, берётся из `bot_settings.default_currency` для чата
(по умолчанию `DEFAULT_CURRENCY` из `.env`, то есть BYN).

## Кто есть кто в чате (учёт по пользователям)

Бот не ограничивается строками имён: он запоминает **участников чата** и привязывает записи к их
Telegram id. Поэтому «Лешак», «Леша» и `@kozlovAlex` в одном чате — один и тот же человек,
и его долги не распадаются на разные имена.

Как это работает:

1. Из каждого сообщения бот берёт автора (id, имя, `@ник`) и сохраняет его в таблицу
   `chat_members` — состав чата собирается сам, по мере общения.
2. Вместе с текстом ИИ получает этот состав и автора сообщения:
   ```
   Участники чата (сопоставляй имена из сообщения с ними):
   - id=101 | Леша Козлов | @kozlovAlex | алиасы: Леша, Лёха
   - id=102 | Дмитрий Болт | @bdzmity | алиасы: Дима, Димон
   Автор сообщения: Леша Козлов (@kozlovAlex) (id=101)
   ```
   Поэтому «Дима» из сообщения превращается в «Дмитрий Болт» (@bdzmity) вместе с его id.
3. Если ИИ не уверен — имя сопоставляет сам бот: по `@нику`, полному или частичному имени,
   падежам («Диме» → «Дима», «Дмитрию» → «Дмитрий») и алиасам. При неоднозначности («Дима»,
   когда в чате два Дмитрия) бот не угадывает, а сохраняет запись по имени.
4. «я», «мне», «меня» — это автор сообщения.
5. Если человек не узнан, бот честно пишет об этом: `ℹ️ Не узнал: Гоша — записал по имени`.

Алиасы можно задать руками — например, в Telegram человек «Александр», а в чате его зовут «Саня»:

```sql
update public.chat_members set aliases = aliases || array['Саня', 'Санёк']
where chat_id = -1001234567890 and user_id = 101;
```

Проверить, кого бот уже знает:

```sql
select user_id, display_name, username, aliases, last_seen
from public.chat_members where chat_id = -1001234567890 order by last_seen desc;
```

Взаимозачёт, итоги и отчёт `/debts` считаются по `user_id`, если он известен, и по имени — если нет
(старые записи и незнакомые люди продолжают работать как раньше).

## Когда бот отвечает, а когда молчит

| Где | Реакция |
|---|---|
| Личный чат | на любое сообщение — обращаться не нужно |
| Группа / супергруппа | только если позвали: `@ваш_бот Леша должен Диме 3`, `/debts@ваш_бот` или **ответ на сообщение бота** |

Упоминание вырезается из текста перед разбором, поэтому `@ваш_бот Леша должен Диме 3`,
`Леша должен Диме 3 @ваш_бот` и `/debts@ваш_бот` понимаются одинаково, а `@Дима` — чужое
упоминание — не мешает записи долга. Остальные сообщения в группе бот просто пропускает
(в логе — «Сообщение N не адресовано боту — пропускаю»).

Настройки в `.env`:

* `REQUIRE_MENTION=1` (по умолчанию) — правило выше; `REQUIRE_MENTION=0` — бот разбирает любое
  сообщение в группе. Для второго варианта в @BotFather нужно отключить privacy mode
  (`/setprivacy` → Disable), иначе Telegram сам не отдаёт боту обычные сообщения;
* `BOT_USERNAME=ваш_бот` — необязательная подсказка с именем бота (без `@`). Обычно имя бот узнаёт
  сам через `getMe`; текущее правило видно в выводе `python bot.py --check`.

## Как формируется запись

DeepSeek вызывается в JSON-режиме (`response_format: json_object`) и обязан вернуть:

```json
{"intent": "debt", "from": "Леша", "to": "Дима", "currency": "BYN", "amount": 3.0, "note": ""}
```

* `intent` — `debt` (долг), `debts` (показать долги), `set_currency` (сменить валюту),
  `help`, `none` (не по теме);
* имена приводятся к именительному падежу («Диме» → «Дима»);
* валюта — код ISO (рубль → BYN, `$` → USD, `€` → EUR, `₽` → RUB и т. д.);
* если DeepSeek недоступен или не ответил — включаются офлайн-эвристики (`heuristic_parse`),
  поэтому базовые фразы бот понимает даже без сети к DeepSeek.

## Как считаются долги

* Записи хранятся «как есть» (кто → кому), а суммы считает Python: в базе ничего не агрегируется.
* Взаимозачёт по паре: `Леша → Дима 3` и `Дима → Леша 1` превращаются в `Леша → Дима 2`.
  Валюты не смешиваются — BYN и USD считаются отдельно.
* Имена сравниваются без учёта регистра, `ё/е` и простых падежей: «Дима», «Диме», «Диму» —
  один и тот же человек (`name_key` в `debts.py`).
* Долги разделены по чатам (`chat_id`): личный чат и семейная группа не пересекаются.

Пример отчёта `/debts`:

```
📊 Долги (записей: 2)

Итог с взаимозачётом:
• Леша → Дима: 2.00 BYN

Итого по людям:
• Леша должен: 2.00 BYN
• Дима должны: 2.00 BYN

Сумма записей без взаимозачёта: 4.00 BYN

Все записи:
• Леша → Дима: 3.00 BYN
• Дима → Леша: 1.00 BYN
```

## Тесты

```powershell
python -m unittest tests.test_pipeline -v
```

Без сети проверяется всё основное: разбор фраз, падежи и регистр имён, взаимозачёт,

## Где запускать

| Вариант | Плюсы | Минусы |
|---|---|---|
| ПК (`python bot.py`) | проще всего начать | нужен включённый ПК |
| Вебхук на Vercel / PythonAnywhere | бесплатно, ответы за 1–3 с, сервер не нужен | нужно один раз настроить адрес и `WEBHOOK_SECRET` |
| VPS / HidenCloud / Render | бот работает всегда | нужен хостинг (у части сервисов есть бесплатный тариф) |
| Android + Termux | без ПК и без облака | Android усыпляет фоновые процессы, нужен `termux-wake-lock` |

Для Termux: `pkg install python`, `pip install requests`, положить проект в `~/debt_calculator`,
создать `.env` и запускать `termux-wake-lock && python bot.py &`.

**Нужны мгновенные ответы (ответ за 1–3 секунды)?** Два пути, оба описаны в
[README_HOSTING.md](README_HOSTING.md):

* **вебхук** — бесплатно на serverless-хостинге (Vercel, PythonAnywhere): Telegram сам присылает
  апдейты на `webhook.py`, постоянный процесс не нужен:
  ```powershell
  python bot.py --set-webhook https://<проект>.vercel.app/api/telegram
  ```
* **ветка `hosting`** — постоянный процесс (long polling) на панели хостинга/VPS; в этой ветке
  cron в Actions отключён (чтобы не конкурировать за апдейты), добавлены `start.sh` и `Procfile`.

## Вариант: полностью в GitHub Actions (без ПК и без хостинга)

Бот умеет работать «пачками»: раз в 30 минут GitHub поднимает runner, забирает накопившиеся
сообщения Telegram, отвечает на них и завершается. Локально это тот же режим:

```powershell
python bot.py --once      # то, что запускает workflow
```

* `.github/workflows/bot.yml` — расписание `cron: "*/30 * * * *"` плюс кнопка **Run workflow**
  (обработать сообщения прямо сейчас, с телефона);
* смещение обработанных апдейтов (`last_update_id`) хранится в таблице `bot_state`,
  поэтому сообщения не теряются и не обрабатываются дважды;
* `concurrency: debt-bot` — защита от параллельных запусков: два `getUpdates` дают HTTP 409.

> ⚠️ Выбирайте **один** режим. Если `python bot.py` уже запущен на ПК/VPS (long polling),
> то запуск из Actions может получить `HTTP 409 Conflict` и упасть: Telegram отдаёт апдейты
> только одному «слушателю». Остановите локальный процесс перед использованием расписания.

### Настройка (5 минут)

1. Загрузить проект в репозиторий GitHub и выполнить `db/schema.sql` в Supabase.
2. Settings → Secrets and variables → Actions → **New repository secret**:
   `TELEGRAM_BOT_TOKEN`, `DEEPSEEK_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`.
   Необязательно (вкладка *Variables*): `DEFAULT_CURRENCY`, `ALLOWED_USER_IDS`.
3. Вкладка **Actions** → включить workflows → **Run workflow**: бот обработает то, что накопилось.
   В логе будет видно шаг «Диагностика: настройки и сервисы» и количество обработанных сообщений.

### Плюсы и ограничения

| Плюсы | Минусы |
|---|---|
| не нужен ПК, хостинг и телефон | **ответ приходит с задержкой** до 30–40 минут (интервал + задержки GitHub) |
| бесплатно для публичных репозиториев | у приватных тратятся минуты: ~45 с × 48 запусков ≈ 1 100 мин/мес из 2 000 |
| тот же код и секреты, переписывать ничего не надо | **вебхук здесь не живёт**: Actions не принимает входящие HTTP-запросы (для вебхука — Vercel/PythonAnywhere) |
| каждый запуск — отдельный лог с диагностикой | расписания отключаются после ~60 дней неактивности репозитория |

Итог: для домашнего бота это рабочий вариант «совсем без инфраструктуры».
Нужны ответы за секунды — включите вебхук (`python bot.py --set-webhook …` на Vercel или
PythonAnywhere) либо держите постоянный процесс (`python bot.py`) на VPS/Termux:
см. [README_HOSTING.md](README_HOSTING.md).

## Что реализовано

* **Привязка к участникам чата** — записи хранятся на Telegram id (`chat_members`, а также
  `from_user_id` / `to_user_id` в `debts`): «Лешак», «Леша» и `@kozlovAlex` — один человек,
  а имя и `@ник` бот показывает в ответе и в отчёте.
* **Возврат долга** — «Леша вернул Диме 3 рубля» (тип записи `repayment`): хранится в той же
  таблице `debts` с колонкой `kind`, взаимозачёт и итоги вычитают возвраты.
* **Тип операции определяет ИИ** — «должен/занял» → долг, «вернул/отдал/погасил» → возврат
  (офлайн-эвристики работают так же, если DeepSeek недоступен).
* **Команда `/undo`** — удаляет последнюю запись чата (и долг, и возврат) с показом того, что убрали.
* **Режим обращения** — в группах бот отвечает только на `@бот …`, `/команда@бот` или ответ на его
  сообщение (`REQUIRE_MENTION`).
* **Вебхук** — мгновенные ответы на Vercel/PythonAnywhere без постоянного процесса (`webhook.py`).

## Ограничения и что можно добавить дальше

* **Удаление записи по номеру** из `/debts` (сейчас `/undo` умеет только последнюю).
* **Минимальный набор переводов** (сейчас взаимозачёт по парам, без «треугольников»).
* **Кнопки «вернул долг»** под отчётом (`inline_keyboard`) — закрывать долг в один тап (нужно
  добавить обработку `callback_query`).
* **Напоминания** по расписанию («кто давно не отдавал») — cron + `sendMessage`.
