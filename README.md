# 💸 Калькулятор долгов (Telegram-бот + DeepSeek + Supabase)

Бот принимает сообщения вида «Леша должен Диме 3 рубля», разбирает их через **DeepSeek**,
складывает структуру в **Supabase** и умеет показывать и считать долги (с взаимозачётом
и валютой по умолчанию).

```
Telegram → bot.py ── DeepSeek (chat/completions, JSON) ──► {"from":"Леша","to":"Дима","currency":"BYN","amount":3.0}
              │
              └── Supabase SDK (PostgREST) → таблицы debts / bot_settings
```

| Файл | Что делает |
|---|---|
| `bot.py` | запуск бота, маршрутизация команд, `--check`, `--demo`, команды вебхука |
| `webhook.py` | режим вебхука: WSGI-приложение (Vercel, PythonAnywhere, gunicorn) + `--serve` |
| `api/telegram.py` | точка входа для Vercel: отдаёт `webhook.app` по адресу `/api/telegram` |
| `telegram_api.py` | Telegram Bot API: `getUpdates`, `sendMessage`, `setWebhook`/`deleteWebhook`, `setMyCommands` |
| `deepseek.py` | разбор сообщений через DeepSeek + офлайн-эвристики (фолбэк) |
| `storage.py` | Supabase через официальный SDK (supabase-py) + хранилище в памяти для тестов |
| `debts.py` | нормализация имён, взаимозачёт, итоги, тексты ответов |
| `members.py` | участники чата: сопоставление имён с `@никами` и id, алиасы из `/reg`, подсказки для ИИ |
| `rates.py` | курсы валют ExchangeRate-API: загрузка раз в день в 12:00 по Минску, хранение, пересчёт по дате записи |
| `config.py` | настройки из `.env` и переменных окружения |
| `db/schema.sql` | таблицы `debts`, `chat_members`, `currency_rates`, `bot_settings`, `bot_state`, RLS, индексы |
| `db/grants.sql` | права для роли `service_role` (если база отвечает `permission denied for schema public`) |
| `tests/test_pipeline.py` | тесты без внешних сервисов (`unittest`) |

Зависимости — `requests` (Telegram Bot API, DeepSeek, курсы валют) и `supabase` (официальный
SDK: только он ходит в базу, внутри те же запросы PostgREST). Работает и на ПК, и на VPS,
и на телефоне в Termux.

## Быстрый старт

1. **Бот.** В Telegram у `@BotFather`: `/newbot` → получить токен.
2. **DeepSeek.** platform.deepseek.com → *API keys* → создать ключ (нужен баланс).
3. **Supabase.** Создать проект → *SQL Editor* → выполнить `db/schema.sql`
   → *Project Settings → API Keys → «Publishable and secret API keys» → Secret keys*:
   взять `Project URL` и **secret-ключ** `sb_secret_…` (публичный publishable не подойдёт —
   с ним запись в базу отклоняет RLS).
4. **Настройки.** Скопировать `.env.example` в `.env` рядом с `bot.py` и заполнить:
   ```ini
   TELEGRAM_BOT_TOKEN=123456789:AA...
   DEEPSEEK_API_KEY=sk-...
   SUPABASE_URL=https://xxxx.supabase.co
   SUPABASE_SECRET_KEY=sb_secret_...     # secret-ключ, не publishable!
   DEFAULT_CURRENCY=BYN
   ALLOWED_USER_IDS=                    # пусто = всем; иначе список id через запятую
   ```
   Узнать свой user id можно у `@userinfobot`.
   Ключи и настройки бот читает **только из `.env` и переменных окружения** — в `config.py`
   (или другой файл кода) их прописывать не нужно: он лишь читает значения, а секреты в git
   попадать не должны.
   Если Supabase отвечает `permission denied for schema public` (42501) — запустите
   `python bot.py --check`: он покажет тип ключа и какой из двух режимов заголовков принимает
   база; при необходимости поставьте `SUPABASE_KEY_HEADER=both` (см. `.env.example`).
   Прежние имена ключа (`SUPABASE_SERVICE_KEY`, `SUPABASE_KEY`) и legacy-ключ
   service_role тоже работают — можно оставить как есть, но новый secret-ключ
   бот предпочтёт, если заданы оба.
5. **Проверка и запуск:**
   ```powershell
   pip install -r requirements.txt
   python bot.py --check     # проверяет .env, Telegram, DeepSeek, Supabase
   python bot.py --demo      # демонстрация без Telegram (в памяти, офлайн-разбор)
   python bot.py             # рабочий режим (Ctrl+C — остановка)
   ```

Список команд бот объявляет в Telegram сам при запуске. Если работаете через вебхук
(постоянный процесс не запускается), сделайте это один раз вручную:
`python bot.py --set-commands` — после этого команды появляются в меню «/», а в ответах
бота они нажимаемые. Среди них `/login` (вход, если чат с паролем) и `/reg` (регистрация):
бот показывает их тем, кто ещё не вошёл или ещё не отметился, и любую из них можно нажать —
команда подставится в строку ввода, останется дописать пароль или имена.

## Что понимает бот

| Что написать | Что произойдёт |
|---|---|
| `@бот Леша должен Диме 3 рубля` (в группе) | долг: Леша → Дима, 3.00 BYN — в группах бот реагирует только на обращение |
| `Леша должен Диме 3 рубля` (в личке) | долг: Леша → Дима, 3.00 BYN (обращаться не нужно) |
| `Леша должен Диме 3 рубля` | долг: Леша → Дима, 3.00 BYN |
| `Маша заняла у Пети 10$` | долг: Маша → Петя, 10.00 USD |
| `Петя должен Оле 10,50 долларов` | долг: Петя → Оля, 10.50 USD |
| `Леша должен Диме 7` | 7.00 в валюте по умолчанию |
| `Леша вернул Диме 3 рубля` | возврат долга: уменьшает долг Леши перед Димой (годится «отдал», «погасил», «рассчитался с Димой на 5») |
| `Лешак должен Диме 3 рубля` | если в чате есть «Леша Козлов» (@kozlovAlex) и «Дмитрий Болт» (@bdzmity), запись привяжется к их id — см. «Кто есть кто в чате» |
| `я должен Диме 3 рубля` | долг записывается на автора сообщения (его id и имя) |
| `/reg Женя, ЖеняШ, шаман, жена` | регистрация: как ещё вас зовут в чате — после неё бот ведёт записи на вас. Команда нажимаемая: бот показывает `/reg` тем, кто ещё не отмечен |
| `/reg @Genia Женя, женя, жекич` | регистрация другого участника по `@нику` (его id бот уже знает) |
| `/who` | состав чата: кто зарегистрирован и по каким именам его узнают |
| `Дима заплатил 10 за всех` | общий счёт: 10.00 делится поровну между зарегистрированными участниками |
| `я заплатил 10` | то же: платил автор сообщения, сумма делится на всех |
| `Маша оплатила ужин 30 рублей за всех кроме Оли` | общий счёт с исключением: Оля в делёж не входит |
| `я заплатил 9 за всех кроме себя` | делёж на остальных: свою долю плативший сам себе не должен |
| `Дима оплатил 6 за Машу и Олю` | общий счёт только на этих двоих |
| `/currency USD` или `валюта по умолчанию доллар` | меняет валюту по умолчанию для чата |
| `/d` | приводит все долги к валюте чата по курсу **на дату каждой записи** (см. ниже) |
| `/rates` | курсы валют (бел. и рос. рубли, доллар, евро, юань, бат) и дата обновления |
| `/settle` (`/offset`, `/зачёт`) | взаимозачёт: минимум переводов, чтобы все долги закрылись |
| `/debts` или `покажи долги` | отчёт: сальдо с взаимозачётом, минимум переводов, итоги по людям, блоки общих счетов и возвратов |
| `/mydebts` (`/me`, `/мои`) | личные итоги: «вы должны» и «вам должны» с итогом по каждому блоку — без разбора всего отчёта |
| `/export` (`/report`, `/txt`) | присылает **файлом CSV** копию таблицы `debts` этого чата: первая строка — названия колонок как в базе, дальше по строке на запись (кавычки, запятые и переносы строк экранированы) |
| чистая личная сводка | `/mydebts` показывает `🎉 Чисто`, если вы никому не должны и вам никто не должен |
| `/status` (`/статус`) | диагностика в чате: отвечает ли база (и сколько в ней записей и участников), есть ли курсы на сегодня, задан ли ключ ИИ, валюта и режим обращения |
| любая запись (долг, возврат, общий счёт) | запись подтверждается **ровно одной строкой** и больше ничем: `✅ @кто → @кому 3.00 BYN`, `↩️ @кто → @кому 3.00 BYN — возврат`, `🧾 @кто заплатил 10.00 BYN — по 2.00 BYN с @a, @b`. Ни итогов, ни подсказок бот в ответе не пишет, чтобы не засорять чат — суммы целиком дают команды `/settle` и `/debts` |
| `/undo` | удаляет последнюю запись этого чата (общий счёт убирается целиком, а не одной долей) |
| `/reset` | удаляет все записи этого чата |
| `/help`, `/start` | справка |
| `/login` | вход: если чат защищён паролем — `/login` просит прислать пароль (`/login ваш-пароль` вводит сразу); если пароля нет — сообщает, что вход не нужен. Команда нажимаемая |
| `/password <пароль>` | то же, что `/login` (псевдонимы входа: `/pass`, `/auth`, `/войти`, `/вход`) |

Валюта, если она не указана в сообщении, берётся из `bot_settings.default_currency` для чата
(по умолчанию `DEFAULT_CURRENCY` из `.env`, то есть BYN).

## Кто есть кто в чате (учёт по пользователям)

Бот не ограничивается строками имён: он запоминает **участников чата** и привязывает записи к их
Telegram id. Поэтому «Лешак», «Леша» и `@kozlovAlex` в одном чате — один и тот же человек,
и его долги не распадаются на разные имена.

Как это работает:

1. Из каждого сообщения бот берёт автора (id, имя, `@ник`) и сохраняет его в таблицу
   `chat_members` — состав чата собирается сам, по мере общения.
2. **Регистрация (`/reg`)** — человек подтверждает, как его зовут в чате, и с этого момента записи
   ведутся на него:
   ```
   /reg Женя, ЖеняШ, женя, жена, шаман, жекич     # про себя: как меня ещё зовут
   /reg @Genia Женя, женя, жекич                  # про другого участника по @нику
   /who                                           # посмотреть, кто уже зарегистрирован
   ```
   Повторы не дублируются («женя» и «Женя» — одно имя), старые имена сохраняются, а отметка
   `is_registered` живёт в `chat_members`.
3. Записи (долг, возврат, общий счёт) сохраняются **только на зарегистрированных**. Если имя в
   сообщении ни с кем не связано или человек ещё не выполнил `/reg`, бот ничего не пишет и
   подсказывает, что делать:
   ```
   ❌ Не записал: записываю только на зарегистрированных участников.
   • Ещё не зарегистрирован: Гоша Петров (@gosha_p)

   Регистрация — командой /reg (её можно нажать):
   • себя: /reg Женя, ЖеняШ, как вас ещё зовут
   • другого: /reg @его_ник Гоша, Гоша Петров, кличка
   После регистрации повторите сообщение — тогда и запишу.
   Кто уже есть в чате: /who
   ```
   Если отметки нет у самого автора сообщения, бот дописывает эту подсказку в конец ответа
   (`/mydebts` новичка, «привет» и любое другое сообщение, которое бот не разобрал) — `/reg`
   из неё тоже нажимаемый:
   ```
   Вы ещё не отмечены в этом чате — нажмите /reg и напишите свои имена:
   • /reg Женя, ЖеняШ, как вас ещё зовут
   ```
4. Вместе с текстом ИИ получает состав чата и автора сообщения:
   ```
   Участники чата (сопоставляй имена из сообщения с ними):
   - [зарегистрирован] id=101 | Леша Козлов | @kozlovAlex | алиасы: Леша, Лёха
   - [не зарегистрирован] id=106 | Гоша Петров | @gosha_p
   Автор сообщения: Леша Козлов (@kozlovAlex) (id=101)
   ```
   Поэтому «Дима» из сообщения превращается в «Дмитрий Болт» (@bdzmity) вместе с его id, а
   «Лешак» узнаётся как Леша Козлов — модель выбирает наиболее вероятного человека по составу чата.
5. Если ИИ не уверен — имя сопоставляет сам бот: по `@нику`, полному или частичному имени,
   падежам («Диме» → «Дима», «Оле» → «Оля», «Дмитрию» → «Дмитрий»), алиасам из `/reg` и похожему
   написанию («Лешак» ≈ «Леша»). При неоднозначности («Дима», когда в чате два Дмитрия) бот не
   угадывает.
6. «я», «мне», «меня» — это автор сообщения.

Проверить, кого бот уже знает (и зарегистрирован ли человек):

```sql
select user_id, display_name, username, aliases, is_registered, last_seen
from public.chat_members where chat_id = -1001234567890 order by last_seen desc;
```

Взаимозачёт, итоги и отчёт `/debts` считаются по `user_id`, если он известен, и по имени — если нет
(старые записи, сделанные до появления регистрации, продолжают работать как раньше).

## Когда бот отвечает, а когда молчит

| Где | Реакция |
|---|---|
| Личный чат | на любое сообщение — обращаться не нужно |
| Группа / супергруппа | если позвали: `@ваш_бот Леша должен Диме 3`, `/debts@ваш_бот`, **ответ на сообщение бота** или **команда в начале сообщения** (`/help`, `/debts`, `/settle`) |

Команды в начале сообщения считаются обращением к боту — писать `@ваш_бот` рядом с `/help`
не нужно. Telegram с включённым privacy mode и сам присылает боту в группы команды и обращения,
так что молчать на `/debts` бот не должен. Чужие команды при этом игнорируются:
`/help@другой_бот` останется без ответа, как и «путь» вида `/usr/bin/ls`.

Упоминание вырезается из текста перед разбором, поэтому `@ваш_бот Леша должен Диме 3`,
`Леша должен Диме 3 @ваш_бот` и `/debts@ваш_бот` понимаются одинаково, а `@Дима` — чужое
упоминание — не мешает записи долга. Остальные сообщения в группе бот просто пропускает
(в логе — «Сообщение N не адресовано боту — пропускаю»).

Настройки в `.env`:

* `REQUIRE_MENTION=1` (по умолчанию) — правило выше; `REQUIRE_MENTION=0` — бот разбирает любое
  сообщение в группе. Для второго варианта в @BotFather нужно отключить privacy mode
  (`/setprivacy` → Disable), иначе Telegram сам не отдаёт боту обычные сообщения;
* `BOT_USERNAME=ваш_бот` — необязательная подсказка с именем бота (без `@`). Обычно имя бот узнаёт
  сам через `getMe`; текущее правило видно в выводе `python bot.py --check`.

## Как формируется запись

DeepSeek вызывается в JSON-режиме (`response_format: json_object`) и обязан вернуть:

```json
{"intent": "debt", "from": "Леша", "to": "Дима", "currency": "BYN", "amount": 3.0, "note": ""}
```

* `intent` — `debt` (долг), `repayment` (возврат), `expense` (общий счёт: кто-то заплатил за всех),
  `debts` (показать долги), `set_currency` (сменить валюту), `help`, `none` (не по теме);
* имена приводятся к именительному падежу («Диме» → «Дима»);
* валюта — код ISO (рубль → BYN, `$` → USD, `€` → EUR, `₽` → RUB и т. д.);
* у общего счёта (`expense`) дополнительно приходят `participants` (за кого платили; пусто — за всех)
  и `exclude` (кого исключить: «кроме Оли», «кроме себя»);
* если DeepSeek недоступен или не ответил — включаются офлайн-эвристики (`heuristic_parse`),
  поэтому базовые фразы бот понимает даже без сети к DeepSeek.

## Как считаются долги

* Записи хранятся «как есть» (кто → кому), а суммы считает Python: в базе ничего не агрегируется.
* Взаимозачёт по паре: `Леша → Дима 3` и `Дима → Леша 1` превращаются в `Леша → Дима 2`.
  Валюты не смешиваются — BYN и USD считаются отдельно.
* Имена сравниваются без учёта регистра, `ё/е` и простых падежей: «Дима», «Диме», «Диму» —
  один и тот же человек (`name_key` в `debts.py`).
* Долги разделены по чатам (`chat_id`): личный чат и семейная группа не пересекаются.

### Ответ на запись: ровно одна короткая строка

Подтверждая запись (долг, возврат или общий счёт), бот пишет **одну строку** — кто, кому и сколько —
и больше ничего: ни итогов, ни подсказок, чтобы чат не засорялся. Суммы целиком дают команды
`/settle` (минимум переводов) и `/debts` (полный отчёт).

```
👤 Леша должен Диме 3 рубля
🤖 ✅ @kozlovAlex → @bdzmity 3.00 BYN
```

```
👤 Леша вернул Диме 1 рубль
🤖 ↩️ @kozlovAlex → @bdzmity 1.00 BYN — возврат
```

```
👤 Дима заплатил 10 за всех
🤖 🧾 @bdzmity заплатил 10.00 BYN — по 2.00 BYN с @kozlovAlex, @petrova_m, @olga_s, @petya_k
```

Если в счёт кого-то не взяли, ответ остаётся одной строкой, а незарегистрированные
перечисляются отдельной строкой с нажимаемой командой:

```
👤 Дима заплатил 10 за всех
🤖 🧾 @bdzmity заплатил 10.00 BYN — по 2.50 BYN с @kozlovAlex, @petrova_m, @olga_s, @petya_k
   ⚠️ Не участвуют (нет /reg): Гоша Петров (@gosha_p)
```

* люди называются коротко: `@ник`, а если ника у человека нет — только имя;
* в общем счёте сразу видно платившего, сумму и долю каждого; исключённые дописываются в той
  же строке — `… (без @olga_s)`, а незарегистрированные — отдельной строкой с командой `/reg`;
* если участников много, перечень имён сворачивается: `… с @a, @b и ещё 2`;
* полные имена (`Леша Козлов (@kozlovAlex)`) бот по-прежнему пишет в отчётах `/debts`, `/d`,
  `/settle` и `/mydebts` — там подробности нужны;
* про суммы бот напоминает не в ответе о записи, а командой: `/settle` (`/offset`, `/зачёт`) —
  минимум переводов, чтобы всё закрылось, и `/debts` — полный отчёт.

### Взаимозачёт: минимум переводов (`/settle`)

Парный зачёт показывает сальдо по парам, а `/settle` отвечает на вопрос «кому и сколько перевести,
чтобы всё закрылось» — цепочки долгов сворачиваются:

```
Леша должен Диме 10, Дима должен Маше 10   →   Леша переводит Маше 10 (один перевод, а не два)
```

```
👤 /settle
🤖 🧮 Минимум переводов, чтобы всё закрылось (валюта чата: BYN):
   • Леша Козлов (@kozlovAlex) → Маша Петрова (@petrova_m): 10.00 BYN
```

* Считается по сальдо каждого человека: сколько он должен минус сколько должны ему, отдельно
  по валютам; затем «жадно» сводятся крупнейший должник и крупнейший кредитор — переводов
  получается не больше, чем людей минус один.
* Возвраты учитываются, взаимные долги гасятся (A→B 10 и B→A 4 → 6).
* Суммы — в валюте чата и по курсу на дату записи (как `/d`), поэтому совпадают с приведённым
  отчётом.
* В `/debts` этот блок появляется сам, если он короче парного зачёта; для простой пары долгов
  он не дублируется.
* Команда понимает и русские названия: `/offset`, `/зачёт`, `/зачет`.

### Общий счёт: «Дима заплатил 10 за всех»

Такую фразу бот считает не долгом одного человека, а **оплатой за всех**: сумма делится поровну
между зарегистрированными участниками чата, и на каждого (кроме платившего) появляется своя доля.

* `Дима заплатил 10 за всех` — в чате 4 зарегистрированных участника (включая Диму) → доля
  каждого `10 / 4 = 2.50`, на Лешу, Машу и Петю записывается по 2.50.
* `я заплатил 10` — то же самое, «я» — автор сообщения.
* `Маша оплатила ужин 30 рублей за всех кроме Оли` — Оля исключена, делим на 3.
* `я заплатил 9 за всех кроме себя` — плативший тоже не участвует в делёж: 9 на 4.
* `Дима оплатил 6 за Машу и Олю` — счёт только на этих двоих: 6 на 3.
* Копейки не теряются: `split_amount` считает в копейках, «лишние» копейки достаются первым
  участникам (10 на 3 → 3.34 + 3.33 + 3.33).
* Оригинал сообщения сохраняется в каждой доли (`raw_text`), а все доли одной оплаты получают общий
  `group_id` — поэтому `/undo` убирает весь счёт целиком.
* Незарегистрированные участники в делёж не входят — бот пишет об этом в ответе.

Пример отчёта `/debts`:

```
📊 Долги (записей: 6, из них возвратов: 1)

Итог с взаимозачётом:
• Леша Козлов (@kozlovAlex) → Дмитрий Болт (@bdzmity): 4.00 BYN
• Маша Петрова (@petrova_m) → Дмитрий Болт (@bdzmity): 2.50 BYN
• Петя Кузнецов (@petya_k) → Дмитрий Болт (@bdzmity): 2.50 BYN

Итого по людям (с учётом возвратов):
• Леша Козлов (@kozlovAlex) должен: 4.00 BYN
• Маша Петрова (@petrova_m) должен: 2.50 BYN
• Петя Кузнецов (@petya_k) должен: 2.50 BYN
• Дмитрий Болт (@bdzmity) должны: 9.00 BYN

Общие счета (🧾 сумма счёта делится между участниками):
• 🧾 «Дима заплатил 10 за всех» — платил Дмитрий Болт (@bdzmity), доля 2.50 BYN, должников 3

Возвраты (учтены в зачёте):
• ↩️ Леша Козлов (@kozlovAlex) вернул Дмитрий Болт (@bdzmity): 1.00 BYN
```

Доли общего счёта участвуют в зачёте наравне с обычными долгами: если Дима потом вернёт кому-то
деньги, обычное «вернул» уменьшит сальдо.

## Пароль чата: бот работает только там, где его знают

Если задан `CHAT_PASSWORD`, бот не работает в чате до подтверждения пароля:

1. Бота добавили в группу — Telegram присылает апдейт `my_chat_member`, и бот сразу пишет:
   ```
   👋 Привет! Я калькулятор долгов: «Леша должен Диме 3 рубля», возвраты, общие счета…
   Сначала отметьтесь — нажмите /reg и допишите свои имена: /reg Женя, ЖеняШ.
   Справка: /help

   🔐 Чтобы я начал работать в этом чате, пришлите пароль:
   • нажмите /login — и следующим сообщением пришлите пароль
   • или сразу: /password ваш-пароль
   • или просто сообщением с паролем — второй раз спрашивать не буду.
   ```
2. Кто-то присылает пароль — тапнул `/login` и написал `сезам`, либо сразу `/login сезам`,
   `/password сезам` или просто `сезам`:
   * верный — `✅ Пароль принят — работаю в этом чате` (и напоминание новичку отметиться `/reg`),
     чат запоминается в `bot_settings.is_authorized`;
   * неверный — `❌ Пароль не подошёл` с подсказкой «нажмите /login…», и бот продолжает молчать
     (никакие долги не записываются).
3. До подтверждения бот в этом чате не отвечает на долги, не показывает отчёты и не регистрирует
   участников — только просит пароль.
4. `/login` отвечает и после входа: `✅ Вход в этот чат уже выполнен — пароль принят` — из ответа
   видно, что делать дальше (`/debts`, `/mydebts`, новичку — `/reg`). Там, где пароля нет, бот
   отвечает `🔓 В этом чате пароль не задан — вход не нужен`. Псевдонимы `/password`, `/pass`,
   `/auth`, `/войти`, `/вход` работают так же.

* Пароль проверяется сравнением постоянного времени (`hmac.compare_digest`), в базе не хранится —
  только отметка «чат подтверждён».
* Разрешение — на каждый чат своё: подтвердили в одной группе, в другой спросят снова.
* Бота удалили из чата — отметка сбрасывается, при повторном добавлении пароль спросят опять.
* `CHAT_PASSWORD` не задан — бот работает в любом чате без пароля (как раньше).

## Курсы валют (ExchangeRate-API) и команда `/d`

Курсы берутся из [ExchangeRate-API](https://www.exchangerate-api.com/docs): бесплатный ключ
выдаётся в кабинете [app.exchangerate-api.com](https://app.exchangerate-api.com/) → Dashboard →
API Key. Ключ пишется в `RATES_API_KEY`.

* Без ключа бот работает через открытый эндпоинт `open.er-api.com` — он тоже отдаёт курсы
  ExchangeRate-API, но с лимитом запросов и с обязательной ссылкой на сервис, поэтому в ответе
  `/rates` всегда стоит источник. Хотите только личный кабинет — оставьте `RATES_OPEN_URL` пустым.
* Достаточно **одного запроса в день**: `GET /latest/<база>` возвращает сразу все валюты, из них
  в базу `currency_rates` кладутся только нужные (`RATES_CURRENCIES`) — иначе было бы больше
  сотни строк в сутки.
* В API курсы «обратные» (`conversion_rates[USD] = 0.3077` = сколько USD за 1 BYN), бот
  переворачивает их и хранит как «1 USD = 3.25 BYN».
* Обновление — **само, раз в день в 12:00 по Минску** (`RATES_HOUR=12`), cron не нужен:
  постоянный процесс сам сверяется с расписанием, а режим вебхука делает это при первом
  апдейте после 12:00 (и на проверке живости `GET /`). До 12:00 к API и базе не обращаемся,
  а если курсы за сегодня уже есть — повторных запросов не будет. Вручную:
  ```powershell
  python bot.py --rates            # обновить (если за сегодня ещё не обновляли)
  python bot.py --rates --force    # обновить заново за сегодня
  ```
* Валюты по умолчанию: BYN, RUB, USD, EUR, CNY, THB (`RATES_CURRENCIES`), база — `RATES_BASE`
  (тоже BYN). Курс валюты, которой нет в списке, не сохраняется — покажет `/rates`.
* Курс в базе (`currency_rates.rate`) — **целое число** `bigint`: `курс × 100000000` (10⁸), то
  есть 3.2531 BYN за USD хранится как `325310000`. Дробных значений в базе нет, а точность
  (8 знаков) сохраняется полностью. Пересчёты сумм бот ведёт в `Decimal` и округляет до
  копеек, поэтому курсы «не плывут» из-за ошибок float.

> Обновлялись с прежней версией схемы (rate был `numeric(20, 8)`)? Повторно выполните
> `db/schema.sql` в Supabase — колонка сама переведётся в `bigint` с умножением на 10⁸.

> Про историю: в бесплатном тарифе ExchangeRate-API прошлых дат нет, бот копит по одному снимку
> в сутки. Если на дату записи курса нет (выходной или долг старше первого снимка), берётся
> ближайший сохранённый — обычно предыдущий.

### `/d` — всё в валюте чата по курсу на дату записи

```
👤 /d
🤖 💱 Привёл к BYN по курсу на дату записи:
   • 21.09.2026: 1 USD = 3.25 BYN, 1 EUR = 3.52 BYN

   📊 Долги (записей: 6)
   …
   • Леша Козлов (@kozlovAlex) → Дмитрий Болт (@bdzmity): 32.50 BYN
```

* Целевая валюта — валюта чата (`/currency`, по умолчанию `DEFAULT_CURRENCY`): все записи
  приводятся к ней, даже если были записаны в USD или юанях.
* Курс берётся **на дату сообщения** (`debts.created_at`), а если на этот день курса нет —
  ближайший сохранённый.
* Валюты, курса на которые нет, остаются как есть и перечисляются в шапке:
  `• Без курса оставил: 40.00 PLN`.
* `/rates` — показать курсы, дату обновления и валюту чата.

### `/export` — записи чата файлом CSV

```
👤 /export
🤖 📄 Выгрузка таблицы debts (CSV): записей 2 (chat_id 555).   ← подпись к файлу
   [файл debts_555_2026-09-25.csv]
   id,created_at,chat_id,from_name,to_name,from_user_id,to_user_id,currency,amount,kind,group_id,raw_text
   1,2026-09-21T10:00:00+00:00,555,Леша Козлов,Дмитрий Болт,101,102,BYN,3.00,debt,,Леша должен Диме 3 рубля
   2,2026-09-22T09:30:00+00:00,555,"Дима ""Болт""",Маша Петрова,102,104,USD,10.00,expense,g-1,"Дима сказал ""ок"", 3 рубля"
```

* Файл копирует **строки таблицы `debts` этого чата**: бот берет `chat_id` из сообщения
  (`storage.list_debts(chat_id)`), поэтому чужие чаты в выгрузку не попадают.
* Ничего не пересчитывается: суммы, валюты и типы записей — как в базе. Если нужен пересчёт
  в валюту чата, есть `/d`.
* Формат — **CSV** (`csv.excel`, RFC 4180): разделитель — запятая, первая строка — названия
  колонок, дальше по строке на запись. Экранирование делает стандартный модуль `csv`: поле
  с запятой, кавычкой или переносом строки целиком берётся в кавычки, а кавычки внутри
  значения удваиваются (`""`). Поэтому `raw_text` вида «Дима сказал "ок", 3 рубля» лежит в
  файле как одно поле `"Дима сказал ""ок"", 3 рубля"`, а перенос строки в исходном сообщении
  больше не разъезжается на две записи и не требует замены на `\n` — `csv.reader` вернёт
  текст как есть.
* Имя файла — `debts_<chat_id>_<дата>.csv`, файл приходит документом (`sendDocument`) с типом
  `text/csv`: Excel и Google Sheets открывают его таблицей. В русской локали Excel при двойном
  клике может показать всё в одной колонке — тогда откройте через «Данные → Из текста/CSV»
  и укажите разделитель «запятая».
* Если записей нет, файл не отправляется — бот отвечает сообщением, что выгружать нечего.

## Что реализовано

* **Привязка к участникам чата** — записи хранятся на Telegram id (`chat_members`, а также
  `from_user_id` / `to_user_id` в `debts`): «Лешак», «Леша» и `@kozlovAlex` — один человек,
  а имя и `@ник` бот показывает в ответе и в отчёте.
* **Пароль чата** (`CHAT_PASSWORD`) — при добавлении в чат бот просит пароль и работает только
  там, где его ввели верно; при удалении из чата доступ сбрасывается.
* **Курсы валют** — сами, раз в день в 12:00 по Минску (`RATES_HOUR`), без cron: постоянный
  процесс сверяется с расписанием, а вебхук — при первом апдейте после 12:00; курсы ложатся
  в `currency_rates` (бел. и рос. рубли, доллар, евро, юань, тайский бат) целым числом
  (`курс × 10⁸`); без ключа работает открытый эндпоинт `open.er-api.com`.
* **`/d` — пересчёт по дате** — все долги приводятся к валюте чата по курсу того дня, когда
  их записали; валюты без курса остаются как есть и перечисляются в шапке.
* **`/export` — выгрузка файлом** — бот присылает документ CSV (`text/csv`) с копией строк
  таблицы `debts` этого чата: колонки как в базе, кавычки/запятые/переносы строк внутри значений
  экранированы стандартным CSV-экранированием; если записей нет, файл не отправляется.
* **`/mydebts` — мои долги** — личные итоги по одному человеку: блоки «вы должны» и «вам должны»
  с итогом по каждому, отдельно по валютам; взаимозачёт считается вокруг вас, а записи других
  людей в ответ не попадают. Если долгов нет — `🎉 Чисто`, если записей ещё нет — `📭`.
* **`/status` — диагностика в чате** — отвечает ли база (и сколько в ней записей, возвратов,
  общих счетов и участников), есть ли курсы на сегодня, задан ли ключ DeepSeek и какие правила
  действуют в этом чате (валюта, режим обращения, пароль). Секреты не показываются, а платная
  онлайн-проверка ИИ остаётся за `python bot.py --check`.
* **Нажимаемые команды** — список команд уходит в Telegram через `setMyCommands` при запуске
  бота (`python bot.py --set-commands` — вручную, для режима вебхука): команды видны в меню «/»,
  а команды из ответов бота подсвечены как ссылки — `/login` (вход по паролю чата) и `/reg`
  (регистрация) можно тапнуть, и команда подставится в строку ввода, набирать её руками
  не нужно: бот показывает их тем, кто ещё не вошёл или ещё не отметился.
* **Регистрация `/reg`** — человек (или его товарищ по `@нику`) перечисляет имена, по которым его
  узнают: «Лешак», «Леша», «Саня». Записи ведутся только на зарегистрированных — иначе бот
  объясняет, что нужно сделать. Состав и статусы видны в `/who`. Если отметки нет у самого автора
  сообщения, бот дописывает в ответ «Вы ещё не отмечены в этом чате — нажмите /reg…»: команду
  можно нажать, дописать имена и повторить сообщение.
* **Взаимозачёт** — парный зачёт (A→B 10 и B→A 4 → 6) и минимум переводов по всему чату
  (`/settle`): цепочки «Леша → Дима → Маша» сворачиваются в один перевод «Леша → Маша».
  В ответе о записи бот итоги не печатает — там одна строка (`✅ @кто → @кому 10.00 BYN`),
  а суммы целиком считает команда `/settle`.
* **Общий счёт** — «Дима заплатил 10 за всех», «…за всех кроме Оли», «…кроме себя»: сумма делится
  поровну между зарегистрированными, оригинал сообщения сохраняется, `/undo` убирает счёт целиком.
* **Возврат долга** — «Леша вернул Диме 3 рубля» (тип записи `repayment`): хранится в той же
  таблице `debts` с колонкой `kind`, взаимозачёт и итоги вычитают возвраты.
* **Тип операции определяет ИИ** — «должен/занял» → долг, «вернул/отдал/погасил» → возврат,
  «заплатил за всех/скинулись» → общий счёт (офлайн-эвристики работают так же без DeepSeek).
* **Команда `/undo`** — удаляет последнюю запись чата (долг, возврат или общий счёт целиком).
* **Режим обращения** — в группах бот отвечает только на `@бот …`, `/команда@бот` или ответ на его
  сообщение (`REQUIRE_MENTION`).
* **Устойчивость к сбоям сети** — если база не ответила вовремя (таймаут, обрыв связи, прокси),
  запрос повторяется сам: `SUPABASE_RETRIES` задаёт число повторов (по умолчанию 2 — до трёх
  попыток), в логе видно «повторяю запрос». Если ответа так и нет, бот пишет об этом в чат
  понятным текстом, а не «внутренней ошибкой». Обычная вставка — новый долг — не повторяется:
  повтор создал бы вторую запись, поэтому бот честно просит проверить `/debts` и повторить.
* **Вебхук** — мгновенные ответы на Vercel/PythonAnywhere без постоянного процесса (`webhook.py`).

## Ограничения и что можно добавить дальше

* **Регистрация обязательна** — если человек не сделал `/reg`, записи на него не создаются:
  имя из текста не считается идентификатором. Это сделано намеренно, чтобы «Гоша» из фразы не
  приклеивался к случайному участнику чата.
* **Удаление записи по номеру** из `/debts` (сейчас `/undo` умеет только последнюю).
* **Кнопки «вернул долг»** под отчётом (`inline_keyboard`) — закрывать долг в один тап (нужно
  добавить обработку `callback_query`).
* **Напоминания** («кто давно не отдавал») — по желанию, отдельным скриптом с `sendMessage`.
